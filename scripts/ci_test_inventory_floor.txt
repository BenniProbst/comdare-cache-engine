# WAS DIESE ZAHLEN SIND: je Hardware-Klasse die kleinste Testzahl, die ein RICHTIG
# gebauter Baum dieses Repos auf DIESER Klasse noch haben darf. Faellt 'ctest -N'
# darunter, ist etwas verschwunden -- scripts/ci_test_coverage_guard.sh meldet
# dann einen NENNER-BEFUND (Exit 4).
#
# WELCHE ZEILE GILT, ENTSCHEIDET NICHT DIE MEINUNG, SONDERN DER BAU-BAUM: die
# Wache liest COMDARE_HOST_RUNS_AVX2 und COMDARE_HOST_RUNS_AVX512F aus der
# CMakeCache.txt DESSELBEN Baums, den sie gerade zaehlt. Laesst sich die Klasse
# nicht bestimmen, ist das ABBRUCH (Exit 2) -- nicht die hoechste und nicht die
# niedrigste Annahme.
#
# WARUM SIE IN EINER DATEI STEHEN UND NICHT IM SKRIPT: die Wache bezieht sonst
# JEDE ihrer Zahlen aus dem Baum, den sie gerade prueft. Schrumpft der Baum,
# schrumpfen Zaehler und Nenner gemeinsam und das Verhaeltnis bleibt 'vollstaendig'
# (V-7 FREMDER NENNER). Diese Zahlen sind die einzigen im ganzen Lauf, die der
# gemessene Baum nicht beeinflussen kann: sie stammen aus einem frueher bewusst
# abgenommenen Zustand und aendern sich nur durch einen Menschen in einem eigenen,
# im Diff sichtbaren Commit.
#
# DIE WACHE SCHREIBT DIESE DATEI NIEMALS SELBST. Eine Untergrenze, die sich beim
# Unterschreiten automatisch nachfuehrt, ist keine Untergrenze, sondern ein
# Protokoll des Verfalls. Waechst die Testzahl, sagt die Wache das ausdruecklich
# an und die Zahlen hier gehoeren dann von Hand nachgezogen -- als eigener Commit,
# damit die Aenderung im Diff auffaellt und jemand sie absichtlich verantwortet.
# NACHZIEHEN HEISST ALLE DREI: die Sprossenabstaende (-4 und -2) sind Teil der
# Aussage, nicht Beiwerk.
#
# -- WIE DIE ZAHLEN ENTSTANDEN SIND (nachgemessen, nicht fortgeschrieben) ------
# GEMESSEN am 2026-08-10 in diesem Repo, Stand 83a6d443, Worktree wt-ce-fk,
# Bau-Baum build-covguard (GCC 15.3.0, Ninja, offizieller Weg:
# './configure.sh --with-generator=Ninja --enable-build-tests --build-dir=...'
# + 2-Pass-Werkzeuge gebaut und neu konfiguriert), Messhost prod1:
#
#     ctest --test-dir build-covguard -N | sed -n 's/^ *Test *#[0-9][0-9]*: *//p' \
#         | LC_ALL=C sort -u | wc -l    ->    496
#
# Dieser Messhost ist die REICHSTE Klasse: CMakeCache.txt meldet
# COMDARE_HOST_RUNS_AVX2=1 UND COMDARE_HOST_RUNS_AVX512F=1. 496 ist damit die
# Untergrenze fuer 'avx512f' und fuer sonst keine.
#
# DIE BEIDEN ANDEREN SPROSSEN SIND NICHT GERECHNET, SONDERN VON CMAKE ERZEUGT
# (Gegenorakel, V-7: die Zahl kommt aus einer anderen Quelle als der Rechnung).
# Verfahren: denselben Baum mit erzwungener Klasse neu KONFIGURIEREN (kein Neubau)
# und die Namensmengen vergleichen --
#     cmake -S . -B build-covguard -DCOMDARE_HOST_RUNS_AVX512F=0                  -> 492
#     cmake -S . -B build-covguard -DCOMDARE_HOST_RUNS_AVX2=0 -DCOMDARE_HOST_RUNS_AVX512F=0 -> 490
# und danach 'cmake -U COMDARE_HOST_RUNS_AVX2 -U COMDARE_HOST_RUNS_AVX512F', damit
# die Probe wieder echt laeuft. Die Wiederherstellung ist nachgewiesen: 496 Tests,
# Namensmenge Byte-gleich zur Erstmessung. Die Differenzen sind NAMENTLICH belegt,
# in beide Richtungen (die Gegenrichtung war jeweils LEER -- es kommt nichts hinzu):
#
#   avx512f -> avx2  verliert genau diese VIER:
#       test_ap5_simd_extension_coherence      (Block an AVX2 UND AVX512F, tests/unit/CMakeLists.txt:4165)
#       test_buildvariant_dll_real             (Block an AVX2 UND AVX512F, tests/unit/CMakeLists.txt:4165)
#       test_simd_add_u64_carry_avx512         (do_run an AVX512F, tests/unit/CMakeLists.txt:5375)
#       test_simd_field_sum_dispatch_avx512    (do_run an AVX512F, tests/unit/CMakeLists.txt:5343)

#   avx2 -> basis    verliert zusaetzlich diese ZWEI:
#       test_simd_add_u64_carry_avx2           (do_run an AVX2, tests/unit/CMakeLists.txt:5372)
#       test_simd_field_sum_dispatch_avx2      (do_run an AVX2, tests/unit/CMakeLists.txt:5330)
#
# Mehr ISA-gattierte Registrierungen gibt es nicht: 'COMDARE_HOST_RUNS' kommt in
# tests/unit/CMakeLists.txt an genau neun Stellen vor --
#   VIER Proben-Definitionen  4129, 4130, 5292, 5293  (dieselben zwei
#       check_cxx_source_runs-Aufrufe stehen ZWEIMAL in der Datei; der zweite ist

#   EINE Block-Bedingung      4165  (if(AVX2 AND AVX512F) -> die zwei add_test in

#   VIER do_run-Argumente     5330, 5343, 5372, 5375

#
# -- WIDERRUF: WAS DIE VORIGE FASSUNG DIESES ABSATZES BEHAUPTETE ---------------
# Sie nannte fuenf Zeilenanker (4134, 5249, 5262, 5291, 5294) und die Aufteilung

# 'ctest -N', NICHT fuer die Wache. Auf einem so erzwungenen Baum bricht
# scripts/ci_test_coverage_guard.sh seit 2026-08-10 mit Exit 2 ab -- eine

# EINE VIERTE KLASSE GIBT ES NICHT: 'AVX-512F ohne AVX2' existiert auf keiner

# -- HISTORIE: DIE ALTE ZAHL 488 UND WARUM SIE ZU HOCH WAR ---------------------
# BIS 2026-08-10 stand hier GENAU EINE Zahl, 488, mit dem Anspruch, sie gelte
