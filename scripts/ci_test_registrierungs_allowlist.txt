# HIER STEHT NUR, WAS BEGRUENDET AUSSERHALB DES BAUWEGS LIEGEN DARF.
# Nicht jede Test-Quelldatei muss in jedem Baum uebersetzt werden -- ein Test gegen
# einen optionalen Fremdbaum ist ohne diesen Baum legitim abwesend. Was NICHT legitim
# ist: dass diese Abwesenheit unbemerkt bleibt.
#
# FORMAT je Zeile, drei Felder, '|'-getrennt:
#
#   <test-quelldatei> | <art>:<gegenstand-der-fehlen-muss> | <begruendung>
#
# Feld 2 ist der Kern und der Grund, warum diese Liste kein Freibrief ist: es nennt
# einen GEGENSTAND, dessen ABWESENHEIT die Ausnahme traegt. Die Wache prueft ihn bei
# jedem Lauf nach. Ist der Gegenstand wieder da, ist die Ausnahme ERLOSCHEN und die
# Zeile wird ROT -- ohne dass jemand diese Liste anfassen muss.
# Eine Allowlist ohne diese Gegenprobe waere eine Freistellung mit unbegrenzter
# Laufzeit; genau daran sind die vier unregistrierten Dateien 14 bzw. 68 Tage lang
# nicht aufgefallen.
#
# DREI ARTEN VON GEGENSTAND, und das PRAEFIX benennt die Art (2026-08-10):
#
#   datei:<pfad>                Die Ausnahme traegt, solange der Pfad NICHT existiert.
#                               Geprueft mit '[ -e ]' im Arbeitsbaum -- UND der Pfad muss
#                               ueberhaupt entstehen koennen (s. TOTE AUSNAHME unten).
#   isa:<merkmal>[+<merkmal>]   Die Ausnahme traegt, solange MINDESTENS EIN Merkmal auf
#                               dem Bau-Host fehlt. Bekannt sind genau zwei: avx2 und
#                               avx512f. Geprueft an COMDARE_HOST_RUNS_<GROSS> im
#                               CMakeCache.txt DES GEMESSENEN BAUMS -- also an dem, was
#                               der Bau vorgefunden hat, nicht an /proc/cpuinfo der
#                               Maschine, auf der die Wache gerade laeuft.
#   frist:<JJJJ-MM-TT>          Die Ausnahme traegt bis zu diesem Tag. Danach ROT. Fuer
#                               den Fall, dass es KEINEN erreichbaren Gegenstand gibt --
#                               ein geparkter Posten mit Ablaufdatum statt einer Adresse,
#                               die niemand je belegen kann. Sie ist die SCHWAECHSTE Form:
#                               wer sie benutzt, muss in Feld 3 sagen, wem der Posten
#                               gehoert und woran er haengt.
#
# WARUM ES DIE ZWEITE ART GIBT (Pipeline 15517, ce/development ROT): Feld 2 kannte bis
# dahin nur einen Pfad. Der erste echte Fang der Wache haengt aber an keiner Datei,
# sondern an einem CMake-Gatter ueber der HOST-ISA -- es gibt schlicht keine Datei,
# deren Abwesenheit man dafuer nennen koennte. Die Wache hat richtig gemeldet; das
# Format konnte die Begruendung nicht ausdruecken.
#
# WAS NICHT MEHR GEHT: Feld 2 leer lassen, oder einen Pfad ohne 'datei:' schreiben.
# Beides ist ab jetzt UNPRUEFBAR und damit ROT. Eine Begruendung, die die Wache nicht
# nachpruefen kann, ist keine Begruendung, sondern genau der Freibrief, gegen den diese
# Liste gebaut ist. Ein unbekanntes Praefix und ein unbekanntes ISA-Merkmal sind aus
# demselben Grund ROT und werden nicht geraten.
#
# 'isa:' IST EINE UND-VERKNUEPFUNG, weil das CMake-Gatter eine ist: der Test wird genau
# dann registriert, wenn ALLE genannten Merkmale da sind. Legitim abwesend ist er also
# genau dann, wenn MINDESTENS EINES fehlt. Sind alle da und die Datei fehlt trotzdem im
# Bauweg, ist die Ausnahme ERLOSCHEN -- das ist der Fall, den ein Host mit AVX-512
# erzeugt, wenn jemand die Registrierung entfernt.
#
# TOTE AUSNAHME -- die ZWEITE RICHTUNG von ERLOSCHEN (PA-1, 2026-08-10):
# Bis heute fragte die Wache nur "existiert der Gegenstand WIEDER?". Damit faengt sie den
# Fall, dass er zurueckkehrt -- aber nicht den, dass er NIE zurueckkehren kann. Der zweite
# Fall lag genau hier vor, in allen vier prt-art-Zeilen (Einzelheiten im Block unten).
# Eine 'datei:'-Zeile ist ab jetzt auch dann ROT, wenn KEINE Quelle dieses Repos den ZWEIG
# kennt, in dem der Pfad liegt: weder der Git-Index (getrackte Datei oder Submodul-Gitlink)
# noch eine .gitignore-Regel, und das vom Elternverzeichnis bis hinauf zur Wurzel. Dann hat
# der Gegenstand in diesem Repo keinen Erzeuger, die Zeile koennte per Konstruktion nie
# erloeschen -- und eine Ausnahme, die nie erlischt, ist die Freistellung mit unbegrenzter
# Laufzeit, gegen die diese Liste gebaut wurde.
# ERREICHBAR ist dagegen: ein Pfad unter einem ignorierten Verzeichnis (Bauprodukt), ein
# Pfad unter einem Submodul-Gitlink (auch beliebig tief -- der Inhalt eines nicht
# ausgecheckten Submoduls steht nie im Index), und eine neue Datei in einem vorhandenen
# Verzeichnis. Alle drei sind mit Koeder belegt (tests/unit/test_pa1_tote_ausnahme.cpp).
# WAS DAS NICHT BEWEIST, ausdruecklich: nicht, dass der Gegenstand nie existieren KANN.
# Jemand kann ihn morgen 'git add'en, ein Pruefling-Repo kann eingehaengt werden, ein
# CI-Job kann ihn hineinkopieren. Gemessen ist nur, dass ihn HEUTE keine Quelle dieses
# Repos nennt. Ein Pfad AUSSERHALB des Repos (absolut oder mit '..'-Segment) wird gar
# nicht beurteilt und nie als tot gemeldet; die Wache weist ihre Zahl im Nenner aus.
#
